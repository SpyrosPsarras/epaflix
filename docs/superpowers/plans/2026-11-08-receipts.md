# Receipts archive implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner and the `Servarr users` group upload receipts from Paperless Go or a browser. Paperless-ngx runs OCR, and paperless-gpt fills in shop, date and total through the cluster Ollama.

**Architecture:** A new Argo application `paperless` in `2-k3s/33.paperless/` runs Paperless-ngx with a Valkey sidecar, paperless-gpt and one CronJob. Files live on ZFS dataset `hdd/paperless` on shypowder, shared over NFS. The database lives in the shared CNPG cluster. Paperless logs in through its own OIDC client against Authentik. The rollout is three PRs plus host work on shypowder. Each live step waits for the owner's confirmation.

**Tech stack:** Kustomize, KSOPS/SOPS, Argo CD, Traefik IngressRoute, Authentik blueprints, CNPG `Database`/`DatabaseRole`, Prometheus Operator, promtool, ZFS, nfs-kernel-server, sanoid, prometheus-node-exporter.

**Spec:** `docs/superpowers/specs/2026-11-08-receipts-design.md`.

## Review focus

1. A friend outside `Servarr users` clicks "Sign in with Authentik". Expected: Authentik denies access and no Paperless user is created. Pinned in Task 3 Step 6.
2. An internet client opens `https://paperless.epaflix.com/admin/`. Expected: 403 from Traefik, with no Django login page. Pinned in Task 3 Step 6.
3. User A uploads a receipt. User B, also in `receipts`, lists documents. Expected: B does not see A's receipt but does see the shop name paperless-gpt created for it. Pinned in Task 4 Step 6.
4. A receipt prints no currency. Expected: `Total` has an amount and an empty currency, not NOK. Pinned in Task 4 Step 6.
5. The Paperless pod restarts. Expected: init succeeds on NFS (no `chown` permission error), the Greek and Norwegian Tesseract packs install, and earlier receipts still open. Pinned in Task 3 Step 6.

### Task 1: shypowder storage (host, live)

**Files:** Modify `1-proxmox/shypowder/README.md`.

**Interfaces:**
- Produces: NFS export `/hdd/paperless` with subdirectories `data` and `media`, owned by 1000:1000. Node exporter on `192.168.10.13:9100`.

- [ ] **Step 1: Read state.** On shypowder, run `zpool status hdd`, `zfs list -r hdd` and `pve-firewall status`. Expected: `hdd` online, only `hdd/data` at 128K. Record whether the PVE firewall is on.
- [ ] **Step 2 (owner confirms): Create the dataset.** `zfs create -o atime=off hdd/paperless`, then `mkdir /hdd/paperless/{data,media}` and `chown -R 1000:1000 /hdd/paperless`.
- [ ] **Step 3 (owner confirms): Install the packages and export the dataset.** Install `nfs-kernel-server sanoid prometheus-node-exporter` with apt. Add `/etc/exports.d/paperless.exports` with one entry per worker IP from `kubectl get nodes -o wide` (workers 61 to 65), options `rw,sync,no_subtree_check,all_squash,anonuid=1000,anongid=1000`. `all_squash` maps the image's root init to 1000, so its `chown` does nothing (Review focus 5). Run `exportfs -ra`. If the PVE firewall is on, allow 2049/tcp from the workers and 9100/tcp from the pod network.
- [ ] **Step 4 (owner confirms): Configure snapshots.** In `/etc/sanoid/sanoid.conf`, give `[hdd/paperless]` `hourly = 24`, `daily = 30`, `monthly = 6`, `autosnap = yes`, `autoprune = yes`. Run `systemctl enable --now sanoid.timer`.
- [ ] **Step 5: Verify.**
  - From k3s-worker-61: `mount -t nfs -o nfsvers=4.2 <shypowder>:/hdd/paperless /mnt/x`, then `touch /mnt/x/data/probe && stat -c %u /mnt/x/data/probe`. Expected: `1000`. Remove the probe, then unmount.
  - From a non-worker host such as homepc, the same mount is refused.
  - On shypowder, `sanoid --cron` followed by `zfs list -t snapshot hdd/paperless` shows `autosnap_` snapshots.
  - `curl -s 192.168.10.13:9100/metrics | grep 'node_zfs_zpool_state{state="online",zpool="hdd"}'` returns 1.
- [ ] **Step 6: Document.** In the README, replace "stays installed but unused" with the dataset, export options, sanoid policy, exporter, firewall rules and the Step 5 results. Commit on the PR 1 branch.

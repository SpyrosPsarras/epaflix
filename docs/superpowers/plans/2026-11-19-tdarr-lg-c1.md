# Tdarr for the LG C1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tdarr fixes library files with DTS audio or Dolby Vision in MKV, the `#media` bot can queue a file for it, and configarr scores DTS releases down.

**Architecture:** Tdarr server Deployment plus a node DaemonSet (one node per k3s worker) in namespace `servarr`, all on the shared NFS media volume. One flow built from community flow plugins, stored in Git and seeded into Tdarr. The bot reaches only Tdarr's API.

**Tech Stack:** Kubernetes manifests with kustomize, Argo CD, Tdarr 2.x (`ghcr.io/haveagitgat/tdarr`, `ghcr.io/haveagitgat/tdarr_node`), configarr, OpenClaw `AGENTS.md`, Python `unittest` manifest tests.

**Spec:** `docs/superpowers/specs/2026-11-19-tdarr-lg-c1-design.md`

## Global Constraints

- Tdarr changes a file only if it has a `dts` audio stream, or Dolby Vision profile 8 or single-stream profile 7 in an MKV.
- Video and subtitles are stream-copied. DTS becomes E-AC3 at `640k`. Dolby Vision is stripped with `-bsf:v dovi_rpu=strip=1`.
- Dolby Vision profiles 4 and 5 go to Require Review and are not touched.
- Third-party plugins: Check HDR type and Check DoVi Profile from `nichols89ben/Tdarr_DoVi_Processing`, commit `5be0b5a34114` (resolve to the full SHA), unmodified, fetched at deploy time with a sha256 check. Never committed to this repo (no license).
- Images pinned by tag and digest in `2-k3s/08.servarr/kustomization.yaml` `images:`, like the other servarr apps.
- Transcode cache lives on the NFS media volume (`servarr-media`, subPath `tdarr-cache`), never on a node disk.
- One transcode CPU worker and one health-check CPU worker per node. No GPU workers.
- No ServiceAccount token in any Tdarr pod. The bot gets no write access to the library and no Kubernetes token.
- Comment only the why. Conventional commit titles, no co-author.

## Review Focus

1. A file with neither problem (SDR H.264, HDR10, HDR10+, DV in MP4) must end "not required" and stay byte-identical. Pinned by the flow-routing test in Task 3.
2. A conversion that fails or produces a shorter file must leave the original in place. Pinned by the flow-shape test in Task 3 (duration-ratio and health-check steps sit before Replace Original File, with their failure outputs not connected to it).
3. A Tdarr node killed for memory must not take other pods with it: container memory limit set, cache off the node disk. Pinned by the manifest test in Task 2.
4. A plugin file changed upstream (force-push, tampering) must fail the deploy, not run. Pinned by the sha256 test in Task 2.
5. The bot asked to "convert" anything else (re-encode, downscale, delete) must refuse. Pinned by the AGENTS.md test in Task 4.
